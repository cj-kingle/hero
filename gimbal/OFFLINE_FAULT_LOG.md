# 小陀螺离线停机记录

两块板各自记录，第一次部署需要分别烧录新固件。无需带着 SWD/USB 线旋转。
诊断只增加记录，不调整 PID、转速、超速/堵转门限或控制状态机。

## 复现与读取

1. 烧录两块板的新固件，正常上电准备，再断开调试线测试。
2. 出现异常停机后不要再次使能/继续运行。保持供电至少 1 秒，让前台完成记录。
3. 机构静止后接回调试器，加载对应 ELF。无需为读取而再次下载程序。
4. 在 Ozone 的 Watched Data 中添加并展开 `dbg_fault_log`，同时添加：
   - `dbg_fault_log_valid`：1 表示存在校验通过的事件（可能是当前 RAM 现场，也可能是 Flash 中恢复的现场）。
   - `dbg_fault_log_sequence`：事件序号。
   - `dbg_fault_log_storage`：0 未进行本次写入，1 已写入，2 空间已满，3 写入失败。
   - `dbg_fault_log_reset_flags`：本次开机读取的 RCC CSR 复位标志。
5. 若连接工具必须复位，让程序运行到初始化完成；启动时会从 Flash 恢复最新记录。
   若已经断电，只要此前写入成功，记录同样会恢复。把两块板的结构体数值截图即可分析。

普通按固件所占扇区下载不包含故障区；**整片擦除、单独擦除 sector 10 会删除记录**。
新固件已经留出该区。旧版链接脚本没有这个约束，回退固件时要自行确认擦除范围。
若重新下载固件，必须运行到 `FaultLogBoot()` 完成才能在 RAM 镜像中看到恢复内容。

## 保存内容

- `board`：1 底盘，2 云台；两板 tick 是各自的开机时间，不能直接当作同步时间。
- `event`：1 从 Working 停止，2 上一次仍在 Working 时发生复位，3 HardFault。
- `tick_ms`：停机时间；event 2 是复位前最近一次有效快照时间（约每 10 ms 更新）。
- `reasons`：该板停机原因位图，多个值可能按位或；`peer_reasons` 是底盘收到的上板原因。
- `mode/state/flags/gap_ms`：运行模式、状态、状态标志和该次控制循环间隔。
- `can1_error/can2_error/online_mask/rx_frames`：CAN 错误、在线状态、接收计数。
- 关节速度、参考速度、位置、前一控制步输出力矩；底盘另有四轮反馈转速。
- `reset_flags`、`cfsr/hfsr/bfar/mmfar`：复位和 HardFault 诊断寄存器。

云台 `flags`：bit0 命令在线，bit1 急停，bit4 IMU 就绪，bit5 传输正常，bit8 输出仍使能。
底盘 `flags`：bit0 遥控在线，bit1 急停，bit2 上板在线，bit3 上板输出使能，
bit4 底盘 IMU 就绪，bit5 上板 IMU 就绪，bit6 上板停机锁存，bit7 传输故障，bit8 轮端输出未停止。

上板 `reasons` 常用值：1 命令失联，2 急停，4 配置，8 电机反馈，16 IMU，
64 pitch 限位，128 传输，256 控制周期，512 堵转，4096 超速。
下板 `reasons`：1 遥控失联，2 急停，4 上板失联，16 上板未就绪，32 上板 IMU 未就绪，
64 前台超时，128 传输故障，256 轮端未全部在线，512 Fault 状态，1024 底盘 IMU 未就绪，
2048 yaw 角无效，4096 准备时摇杆未回中，8192 上板停机锁存，16384 上板模式未就绪。
正常人为急停也会产生 event 1，需要结合原因位判断，不能把所有事件都解释为代码异常。

## 保留机制与边界

- 独立 Flash sector 10：`0x080C0000..0x080DFFFF`，128 KiB。
  固件可用 Flash 限为 768 KiB；底盘 sector 11 的 yaw 标定区保留。
- 按槽追加记录、CRC 校验、最后提交。断写后的槽不重用；新启动加载最近一条有效事件。
  空间约可存 936 条事件，写满返回 2，**不自动擦除**，不影响原控制保护逻辑。
- 每次运行只冻结首次停机，后续联动停机不覆盖；保存成功后的下一次 Working 可开启新一轮记录。
  因此异常后不要反复使能再急停，否则 RAM 镜像会显示较新的停止事件，早期事件仍在 Flash 中。
- 运动期间只做 RAM 快照；停止输出并留出至少 50 ms 后才在主循环尝试写 Flash。
  未保存的记录不被新一轮运行覆盖，写失败在本次运行不反复重试。
- RAM 使用启动时不清零的独立区，双份快照带 CRC。看门狗/软件/调试复位后可恢复尚未落盘的现场，
  在启动电机和看门狗前尝试落盘；POR/BOR 后不信任 RAM，只读取已提交的 Flash。
- **若掉电发生在落盘前、CPU 卡死且无复位、或故障破坏了 RAM，不能保证得到完整现场。**
  HardFault 保存 SCB 故障寄存器和最近快照，不保证获取异常指令 PC；不改变原异常处理和看门狗行为。
- 本次验证为两板交叉编译、主机运行测试和 ELF 分区检查；仍需实机复现验证供电、复位和停机现场。
